# Проверка NCCG / Nostra Cura

История первоначальной проверки. Финальное состояние и измерения описаны в SEO-AUDIT-2026-11-02.md. Перенос домена не выполнялся.

## Что исправлено

- Статический HTML для /, /liam и страницы 404: содержимое, уникальные title/description, canonical, Open Graph и Twitter доступны до запуска JavaScript.
- Метаданные обновляются и при переходах внутри React Router. Неизвестные маршруты получают noindex; правила Netlify возвращают 404.
- Organization JSON-LD с названием компании, основателем, логотипом и действующим email; без выдуманных отзывов, адресов и рейтингов.
- Sitemap содержит только главную и Liam, без дублей и 404.
- Все тексты About и Services присутствуют в исходном HTML; скрытые слайды доступны через переключатели.
- Удалены повторяющиеся section id; один H1 на страницу, добавлена ссылка пропуска меню.
- Исправлены смещение Home на 120 px и разная позиция заголовков: на desktop About, Services, Team и Stories начинаются на 104 px от верха после перехода меню.
- Кнопки услуг ведут к рабочей форме; Workbooks предлагает запросить информацию вместо перехода на отсутствующую страницу.
- Контент About, Services и Liam обновлён по двум предоставленным DOCX; роль Liam — Founder & Consultant.
- Добавлен прозрачный логотип для header/footer; оптимизированный WebP занимает около 49 KB. Исходный цветной вариант используется в метаданных.
- Успех основной формы показывается только после успешного HTTP-ответа; honeypot попадает в запрос. Необязательный телефон не блокирует отправку.
- Liam использует нативную проверку email и блокировку повторной отправки. Удалён незавершённый reCAPTCHA-виджет.
- Мобильное меню скрывается из доступности при закрытии, удерживает клавиатурный фокус при открытии и возвращает его на кнопку.
- Убрана бесконечная пульсация стрелок; reduced-motion отключает движение соответствующих фонов и карточек. Основной текст Liam доступен сразу без печати по буквам.

## Проверки

- npm run lint — без ошибок и предупреждений.
- npm run build — TypeScript, Vite и статическая генерация страниц.
- npm test — регрессионные проверки готового HTML, sitemap, структуры заголовков, Netlify-деклараций и внутренних ссылок. Перед тестами требуется сборка.
- Chromium: 1440×900 и 390×844, главная, меню, Services и Liam; проверка горизонтального переполнения, H1, canonical и ошибок JavaScript.
- Формы проверяются с перехваченными ответами сервера: это проверка UI, не доставка реального сообщения через Netlify.
- Проверка Impeccable обнаружила только предупреждение о временном font-family Arial; декларация убрана, сохранена исходная типографика.

## Рекомендации по приоритету

1. Перед публикацией проверить обе формы на реальном Netlify: обнаружение формы, получение сообщения и уведомления владельцу. Локальная успешная заглушка не доказывает доставку.
2. Заменить ссылки социальных сетей в footer на реальные профили либо убрать их: сейчас они ведут на главные страницы платформ.
3. Сделать полноценную страницу Workbooks: темы восьми сессий, пример разворота, формат получения и реальный способ заказа или запроса. Не публиковать выдуманные цены.
4. Для Individuals и Teams уточнить формат работы: кому подходит, как проходит первая беседа, длительность, онлайн/очно, географию обслуживания и следующий шаг. Отдельные страницы услуг дадут прямые ссылки на каждое предложение.
5. Получить исходный SVG логотипа и белую версию для тёмного header/footer. Текущий PNG/WebP имеет белый фон и широкие поля; на небольшом экране подпись мелкая.
6. Дизайн: согласовать одну систему размеров подзаголовков, золотых акцентов и кнопок. Не менять всю визуальную концепцию без отдельного решения. Сохранить читаемый текст вместо попытки уместить любую секцию ровно в экран, особенно при увеличении шрифта.
7. Анимация: реализована смена всей карточки с горизонтальным сдвигом и затуханием за 260 ms. Бесконечная пульсация стрелок и бегущая строка Liam отключены.
8. Контент доверия: добавить подтверждённые кейсы и отзывы с разрешения клиентов. Описывать конкретный процесс и пользу без медицинских обещаний и гарантированных результатов.
9. После публикации проверить URL Inspection, sitemap и индексирование в Google Search Console, затем измерить Core Web Vitals на реальных данных. Текущая проверка не является Lighthouse-аудитом и не обещает SEO-позиции.
10. Переход на nccg.ca выполнить отдельной миграцией: HTTPS, 301 с каждого старого URL на соответствующий новый, обновление canonical/sitemap/JSON-LD и проверка email. В DOCX миграция отложена, поэтому nostracura.ca и действующие email сохранены.

Обоснование статической генерации и отдельных canonical: [Google Search Central — JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).
